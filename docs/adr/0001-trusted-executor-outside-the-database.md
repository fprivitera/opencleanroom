# The executor is a trusted service outside the database; noise never enters the SQL

The original PRD injected noise into the rewritten SQL. Noise generated by the database is floating-point, cannot be verified, and is visible to anyone who can read the query or its plan. An in-process library would show raw aggregates to the consumer. The rewriter therefore only produces SQL with finite sensitivity. A separate executor, deployed as an MCP server, runs that SQL, adds discrete noise with OpenDP and enforces the budget. Consumers, human or agent, talk only to the executor.

## Considered options

- Noise in SQL (`RANDOM()`): rejected. It breaks the floating-point requirement and verifiability.
- In-process library for trusted consumers: rejected as the default. Differential privacy would protect only the published output.
